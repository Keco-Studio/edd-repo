# GDD EDD 玩家评分 Web

独立运行的 GDD EDD 编排与匿名评分服务。管理员一次提交后，服务自动生成关联的 Progression、Problem、Result，并返回玩家链接；玩家提交后，聚合结果自动写回本次新建的 Result。

## 运行

需要 Node.js 20 或更高版本。

```bash
cd docs/gdd-edd/player-rating-web
npm install
npm start
```

启动后终端会打印：

- 玩家入口：用于检查页面，正式链接由管理页生成；
- 管理页面：包含临时管理员令牌，请勿公开；
- 局域网入口：同一网络中的设备可访问。

管理页需要填写执行标识、GDD 引用、AI 两项得分和全部有证据的问题。系统只写入 `../progress/`、`../problem/`、`../result/`，并使用同一执行标识命名三份文档。同名文件已存在时拒绝覆盖。每次启动未设置 `EDD_ADMIN_TOKEN` 时会生成新管理员令牌，但历史评分数据仍保存在 `data/store.json`。

## 公网链接

先在 ngrok 本机配置凭据，再运行：

```bash
npm run share
```

服务会打印公网入口。在管理页生成评分会话后，复制带 `?session=...` 的完整玩家链接。不要把管理链接或管理员令牌发给玩家。

## 评分规则

- 只评价“核心玩法”和“玩家体验”；玩家体验包含 UI 视觉风格与可玩性。
- 玩家每个维度给 1–5 分；收到第一份评分后即生成合并分，没有固定人数门槛。
- AI 占 60%，玩家占 40%；两个维度各占总分 50%。
- 同一浏览器再次提交会更新原评分，不增加样本数。
- 玩家自由文本只保存在 `data/store.json`，不会写入正式结果 Markdown。
- AI 各维度问题扣分合计必须等于 `50 - AI 得分`；50 分时该维度无需添加问题。

## 管理与恢复

- “结束评分”会停止新提交并完成最后一次写回。
- “重新写回”可在 Markdown 同步失败后重试。
- 备份时复制 `data/store.json`；恢复时停止服务、替换该文件后重新启动。
- 文档写回仅替换当前会话的 `EDD_PLAYER_RATINGS_START/END` 标记区块，区块外人工内容不变。

## 检查

```bash
npm test
npm run check
```

测试使用临时目录，不会修改真实结果文档或运行数据。
