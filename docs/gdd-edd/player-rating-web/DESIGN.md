# GDD EDD 玩家评分 Web 设计

## 目标

在 `docs/gdd-edd/player-rating-web/` 内提供一个可独立运行的小型 Web 服务。管理员可以选择 EDD 结果 Markdown、录入 AI 两维度得分并生成公开匿名评分链接；玩家从不同设备提交评分后，服务自动聚合并回写指定结果文档。

## 边界

- 不修改 Keco Studio 主应用、主路由或 Supabase 数据库。
- 项目代码、页面、测试、运行数据与说明全部位于本目录。
- 评分结果只写入 `../result/*.md`，服务拒绝目录穿越与其他扩展名。
- AI 仍只评价“核心玩法”和“玩家体验”，两个维度各从 50 分起算。AI 可针对每个有证据的问题自由决定扣分，不使用固定扣分档位。
- 玩家分别对两个维度给 1 至 5 分；AI 占合并分 60%，玩家占 40%；两个最终维度各占总分 50%。

## 运行方式

- `npm start`：启动本地服务并打印本机和局域网地址。
- `npm run share`：启动服务并创建 ngrok 公网地址。ngrok 凭据仅使用本机安全配置，不写入项目。
- `npm test`：运行 Node 内置测试。

## 页面

### 管理页

管理页通过启动时生成的管理员令牌访问。它负责：

- 从 `../result/` 选择结果 Markdown；
- 输入游戏名、AI 核心玩法得分、AI 玩家体验得分；
- 设置有效期；
- 创建、关闭或重新同步评分会话；
- 显示公开链接、样本数、分布、合并结果和同步状态。

### 玩家页

玩家通过包含随机会话令牌的公开链接访问，不需要 Keco 账号。页面包含：

- 游戏名和简短评分说明；
- 核心玩法 1 至 5 分单选；
- 玩家体验 1 至 5 分单选，说明其包含 UI 视觉风格与可玩性；
- 两组固定问题原因复选框；
- 最多 300 字的可选反馈；
- 提交成功状态及当前样本数。

同一浏览器为同一会话生成稳定匿名标识。重复提交更新原记录，不增加样本数。

## 视觉方向

页面是试玩质检工具，不做营销落地页。使用白色、近黑、叶绿、暖黄和珊瑚红组成克制但非单色的工作界面；以一张温暖手绘猫咪收容场景作为窄幅主题图。评分标尺是页面的主要交互记忆点，五档固定宽度，移动端纵向排列且不缩小点击区域。

## 数据模型

运行数据保存在 `data/store.json`，通过单进程写队列和临时文件原子替换防止并发覆盖。

```text
Session
  id, publicToken, gameTitle, resultDocument, status, expiresAt,
  aiCoreScore, aiExperienceScore, createdAt, updatedAt

Rating
  id, sessionId, respondentHash, coreScore, experienceScore,
  coreReasons[], experienceReasons[], comment, createdAt, updatedAt
```

公开 API 不返回管理员令牌、结果文档路径、AI 原始问题或玩家自由文本。

## 评分计算

```text
AI 核心玩法百分制 = AI 核心玩法得分 / 50 × 100
AI 玩家体验百分制 = AI 玩家体验得分 / 50 × 100
玩家核心玩法百分制 = 玩家核心玩法平均分 / 5 × 100
玩家体验百分制 = 玩家体验平均分 / 5 × 100

最终核心玩法 = AI 核心玩法百分制 × 60% + 玩家核心玩法百分制 × 40%
最终玩家体验 = AI 玩家体验百分制 × 60% + 玩家体验百分制 × 40%
最终总分 = 最终核心玩法 × 50% + 最终玩家体验 × 50%
```

没有玩家评分时不生成合并总分；收到第一份有效评分后即生成合并结果。

## 文档写回

服务在结果文档中维护一个会话专属区块：

```markdown
<!-- EDD_PLAYER_RATINGS_START:<session-id> -->
## 玩家评分与合并结果
...
<!-- EDD_PLAYER_RATINGS_END:<session-id> -->
```

首次同步追加区块；后续同步只替换同一标记之间的内容。每次读取最新文件再写入临时文件并原子替换，保留区块外的人工编辑。区块包含样本数、两个评分的 1 至 5 分完整分布、平均分、高频问题原因、AI/玩家合并公式、最终得分和同步时间。自由文本只保留在本地数据文件，不写入正式结果。

## 安全与滥用控制

- 会话令牌使用加密安全随机数，公开 API 按令牌定位会话。
- 管理 API 需要启动时生成的管理员令牌。
- 按 IP 和会话进行内存速率限制。
- 请求体、评分范围、原因枚举和评论长度均在服务端验证。
- 匿名标识与会话 ID 一起哈希后保存，不保留玩家身份信息。
- 会话可过期或由管理员关闭；关闭后只允许读取汇总，不再接受提交。

## 验证

- 单元测试覆盖评分公式、空样本、分布、匿名更新、路径限制、原子存储和 Markdown 区块替换。
- HTTP 测试覆盖无效令牌、过期/关闭会话、提交校验、重复提交和管理员鉴权。
- 浏览器测试覆盖创建会话、匿名评分、更新评分、文档同步以及桌面/移动端布局。
