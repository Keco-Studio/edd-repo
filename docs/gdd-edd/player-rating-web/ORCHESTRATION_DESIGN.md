# GDD EDD 本地编排设计

## 目标

管理页一次提交执行标识、游戏名、GDD 引用、AI 两维度得分、AI 全部问题和有效期。服务自动创建同标识的 Progression、问题记录、评价结果，并创建玩家评分会话、返回公开链接。

## 边界

- 所有实现仍位于 `docs/gdd-edd/player-rating-web/`。
- 生成文档只允许写入 `docs/gdd-edd/progress/`、`problem/`、`result/`。
- 不修改 Keco Studio 主应用、路由或数据库，不调用外部 AI。
- AI 问题由调用方提供；服务负责结构化记录、关联和汇总，不推测缺失评价。

## 数据流

`POST /api/admin/workflows` 校验稳定执行标识和输入，拒绝覆盖已有同名文件；文档编排器生成三份 Markdown，成功写入后创建评分会话。响应返回三个相对路径、会话和玩家链接令牌。玩家评分继续写回本次自动创建的结果文档。

Progression 记录输入、自动执行步骤、生成文件和待执行玩家评分；Problem 将每条 AI 问题赋予稳定编号并记录维度、扣分、证据和状态；Result 引用 GDD、Progression、Problem、v5 模板，写入 AI 分数与全部问题，预留自动玩家评分标记区块。

## 异常处理

- 执行标识只允许字母、数字、中文、点、短横线和下划线。
- 同标识文件已存在时返回冲突，不覆盖人工内容。
- 任一文档写入失败时不创建评分会话。
- 每个新工作流使用独立结果文件，避免不同会话标记冲突。
