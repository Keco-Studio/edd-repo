# 评价结果目录要求

## 1. 用途

本目录保存 Claude 使用人工提供并锁定的评价模板填写的正式结果。AI 不得在本目录自行创建评价模板。

## 2. 唯一允许的评价维度

正式评价只允许以下两个一级维度：

1. **核心玩法**
2. **玩家体验**

不得增加以下内容：

- 可维护性；
- 可测试性；
- 代码结构或架构质量；
- 开发流程成熟度；
- 不在人工模板中的其他评价维度。

评价维度、指标、扣分和结论格式全部以已确认模板为准。当前生效的 v5 只评价核心玩法和玩家体验，两个维度各占 50%，并合并 AI 60% 与玩家 40% 的评分。

## 3. 结果证据要求

每个正式结果必须引用：

- 人工模板的名称和版本；
- 被评价 GDD 的稳定标识或文件哈希；
- 对应的 Progression 文件；
- 对应的问题记录；
- 使用的游戏构建、运行证据或玩家反馈（存在时）。

GDD 文档评价与游戏产出评价必须区分：

- GDD 文档可以证明设计是否覆盖核心玩法和预期玩家体验。
- 实际游戏产出才能证明游戏是否具备可玩性以及视觉效果是否真实落地。
- 没有运行或人工玩家证据时，实际可玩性必须标记为“待人工验证”或模板规定的等价状态。

## 4. 输出限制

- 不得修改人工模板原文、字段顺序和评分规则。
- 不得因为证据缺失而用模型主观判断补分。
- 不得把疑惑点隐藏在评分说明中；应同步写入对应 `problem` 文件。
- 不得只输出总分，必须保留模板要求的证据引用和结论依据。
- 未完成人工审核的文件必须明确标记为“待人工审核”，不得作为最终结论回传。

## 5. 当前状态

- 唯一保留并生效的模板：`评价模板-v5.md`。
- 使用 v5 时，AI 两个维度各从 50 分起算并自主决定每项扣分；必须列出指标数据和全部有证据的问题。收到玩家评分后，按 AI 60% 与玩家 40% 生成合并总分。
