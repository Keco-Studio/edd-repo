# Progression 执行记录要求

## 1. 用途

AI 默认只向用户展示简洁执行结果，但每次 GDD 生成和评价执行都必须额外保存一份中文 `Progression.md`，供人工审查完整过程。

本目录只保存执行事实，不保存正式评分。

## 2. 必须记录的内容

每份 Progression 记录必须包含以下信息：

1. **执行身份**
   - 人工确认的执行标识；
   - 执行日期和时间范围；
   - 执行模型及可见版本名称；
   - 本次目标；
   - 对应项目、GDS、GDD 或文件标识。
2. **输入材料**
   - 所有输入文件、文档和资源的名称或路径；
   - 输入版本、修订号或内容哈希（可获得时）；
   - 人工指令及中途追加或覆盖的指令；
   - 未提供但会影响执行的材料。
3. **完整执行顺序**
   - 按实际发生顺序编号；
   - 每一步的目标、动作、结果和状态；
   - 发生暂停、恢复、跳过或改道时记录原因；
   - 不得把失败步骤从记录中删除。
4. **工具调用**
   - 工具名称；
   - 调用目的；
   - 与审查相关的输入参数；
   - 返回状态和结果摘要；
   - 产生或修改的文件、文档、任务或资源；
   - 错误、重试和重试结果。
5. **决策与假设**
   - 执行中采用的明确假设；
   - 发生选择时采用的方案及可审查依据；
   - 因用户指令、工具限制或证据变化而作出的调整。
6. **疑惑点**
   - 不确定的问题；
   - 不确定性影响的步骤或评价维度；
   - AI 当时如何处理；
   - 是否需要人工决定；
   - 对应 `problem` 文件中的问题编号。
7. **最终执行结果**
   - 已完成事项；
   - 未完成或未验证事项；
   - 实际产物及路径；
   - 已执行的写操作；
   - 下一人工动作和恢复位置。

## 3. 工具调用记录规则

- 工具调用必须按真实顺序记录，不能只列最终成功调用。
- 同一工具多次调用时逐次记录，不能合并掉失败和重试。
- 返回内容较大时可记录摘要、稳定标识、哈希和证据文件路径，但必须保证人工可以定位原始证据。
- 文件修改必须记录文件路径和修改目的。
- 外部写入必须记录写入对象、结果和回读验证状态。
- 未执行的工具不得写成已执行。

## 4. 安全和推理边界

- 不记录访问令牌、Cookie、密码、私钥、授权头、签名 URL 或其他凭据。
- 敏感参数必须写为“已脱敏”，并说明其用途。
- 不要求或保存模型隐藏思维链。
- 应记录可审查的事实、工具调用、明确决策、简要决策依据、假设和疑惑点。
- 不能用“模型认为”代替证据或工具结果。

## 5. 完整性要求

出现以下任一情况时，Progression 记录不完整：

- 缺少实际调用过的工具；
- 缺少失败、重试或中断记录；
- 未列出疑惑点和证据缺口；
- 只写最终结果，没有过程顺序；
- 声称完成但没有记录回读或验证；
- 泄露敏感凭据；
- 将隐藏思维链作为审查材料。

人工审核通过前，Progression 记录不得移动到正式归档状态。
