# GDD EDD 人工测评流程

> 当前阶段：AI 评价结合独立玩家评分 Web 收集，结果自动回写本地 Markdown。

## 1. 目标

本流程用于记录 GDD 的生成过程，并使用人工提供的固定评价模板完成 EDD 测评。所有过程文档和评价文档使用中文。

评价标准只允许以下两个一级维度：

1. **核心玩法**
2. **玩家体验**：包含 UI 视觉风格和可玩性

不得加入可维护性、可测试性、代码质量、架构质量或其他工程评价维度。游戏产出阶段重点判断游戏是否实际具备可玩性。

## 2. 目录职责

```text
docs/gdd-edd/
├── progress/   AI 执行过程和工具调用记录
├── result/     使用人工模板填写的正式评价结果
└── problem/    疑惑点、证据缺口、冲突和待人工判断事项
```

三个目录的内容不得混用：

- `progress` 记录发生了什么，不负责给分。
- `result` 保存正式评分，不展开执行流水。
- `problem` 保存无法确定、无法评分或需要人工处理的事项。

## 3. 当前人工流程

```text
人工确认 GDS/GDD 目标和输入
  -> Codex 生成 GDD
  -> Codex 写入中文 Progression 执行记录
  -> Codex 将疑惑点和证据缺口写入 problem
  -> 人工审核 GDD、progress 和 problem
  -> 人工将审核包上传到独立 Claude 评分窗口
  -> Claude 严格按人工提供的模板评分
  -> Claude 将评价结果写入 result，将未决事项写入 problem
  -> 人工审核评分结果
  -> 人工将结果回传给 Codex
  -> Codex 根据人工确认的结果继续后续工作
```

双模型分工是当前人工操作约定，不属于本轮系统设计：Codex 负责生成 GDD；Claude 负责评分。当前不实现自动打开 CMD 窗口、自动选择模型、自动上传或自动回传。

## 3.1 本地一键编排

`player-rating-web/` 提供仅限本目录体系的自动编排。管理员提交执行标识、GDD 引用、AI 两项得分和全部问题后，服务自动创建：

- `progress/<执行标识>-Progression.md`；
- `problem/<执行标识>-问题记录.md`；
- `result/<执行标识>-评价结果.md`；
- 绑定该 Result 的匿名玩家评分链接。

玩家评分后，分布、原因和 AI 60%/玩家 40% 的合并结果自动写回对应 Result。服务不修改 Keco Studio 主应用或数据库，也不调用外部 AI。

## 4. 人工模板约束

- 正式评价模板必须由人工提供并确认版本。
- AI 不得生成、补全、改写或替换正式评价模板。
- AI 不得新增评价维度、子评分、权重、总分公式或通过线。
- 模板缺失、版本不明或内容冲突时，不得开始正式评分。
- 模板发生变化后，旧结果仍引用旧模板版本；不得静默重算。
- 人工模板只允许覆盖“核心玩法”和“玩家体验”两个一级维度。

唯一保留并生效的模板为 `result/评价模板-v5.md`。v5 只评价“核心玩法”和“玩家体验”，两个维度各占 50%；AI 自主决定每个有证据问题的扣分并占合并分 60%，玩家 1–5 分占 40%。收到玩家评分后即生成合并总分。

## 5. 证据边界

### 5.1 GDD 文档阶段

只能评价 GDD 是否清楚、完整地定义了：

- 核心玩法；
- 玩家体验，包括 UI 视觉风格和预期可玩性。

GDD 是设计证据，不是实际游戏运行证据。仅凭 GDD 不得断言游戏已经好玩、已经可运行或视觉效果已经达标。

### 5.2 游戏产出阶段

游戏产出评价重点是实际可玩性。评价必须引用真实构建、运行记录、玩家操作或人工玩家反馈。没有这些证据时，应记录为“待人工验证”或“证据不足”，不得由 AI 猜测通过。

视觉评价应基于实际 UI、画面或人工体验证据；不能只根据 GDD 的美术描述给实际游戏视觉效果打分。

## 6. 人工暂停点

以下材料准备完成后必须暂停：

- 待评价 GDD；
- 对应的 `progress` 执行记录；
- 对应的 `problem` 问题记录；
- 人工提供并锁定的评价模板。

暂停后由人工打开独立 Claude 评分窗口并上传材料。AI 不得自行跨过该暂停点。

## 7. 文件关联

同一次执行在三个目录中使用相同的人工确认标识，例如：

```text
progress/<执行标识>-Progression.md
result/<执行标识>-评价结果.md
problem/<执行标识>-问题记录.md
```

`执行标识` 的格式由人工确定。AI 不得自行建立另一套命名规则。每份结果和问题记录必须明确引用对应的 GDD、Progression 文件和人工模板版本。
