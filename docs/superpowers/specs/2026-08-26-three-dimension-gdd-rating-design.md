# GDD 三维评价设计

## 目标

将 AI GDD 评价与玩家 Web 人工评价统一为三个顶层维度，同时保持提示词简短、证据可审计且不增加二级评分。

## 固定维度

| 维度 | AI 分值 | 评价范围 |
| --- | ---: | --- |
| 体验价值 | 30 | 目标玩家、核心幻想、玩家动机、差异化、预期情绪与体验节奏 |
| 玩法与系统 | 40 | 核心循环、操作与选择、规则、反馈、难度、成长、经济和平衡 |
| 内容与呈现 | 30 | 内容结构、关卡、叙事、视觉、音频、UI、信息可读性和风格一致性 |

每个维度只给一个总分。检查范围只用于取证，不生成二级分数。评分统一遵循“体验目标 -> 设计响应 -> 文档证据”，证据缺失时记录缺口，不推测未写内容或实际运行质量。同一证据和同一问题只归入一个主要维度。

## AI 输出

JSON 使用 `experienceValue`、`gameplaySystems`、`contentPresentation` 三个字段，分值上限分别为 30、40、30。每维保留客观观察、GDD 证据、评分理由和证据缺口；问题的 `dimension` 也只能使用这三个值。

提示词只说明评价对象、GDD、固定标尺和四条约束：仅按明确证据、缺失不补全、单一归属、不推测运行质量。结构要求由 JSON Schema 保证，不在提示词中重复展开。

## 人工评分与合并

玩家 Web 对三个相同维度各给 1-5 分。低分时显示该维度的固定原因选项，并保留一条选填备注。

每维先换算为百分制，再执行 `AI 70% + 人工 30%`。最终总分按 `体验价值 30% + 玩法与系统 40% + 内容与呈现 30%` 加权。没有人工样本时只展示 AI 分数，不生成合并总分。

## 版本与兼容

新增三维 rubric 和 Result 模板版本，Eval Case 指向新版本。历史 run2/run3 文档与已运行的旧评分服务不改写；新的评价与基线使用三维 schema，基线 schemaVersion 升级以拒绝误用旧两维基线。

## 验证

通过单元测试覆盖 AI 校验、人工输入校验、聚合与加权、文档渲染、页面三组评分、API 提交、三文档回写和三维采样统计；最后运行完整测试与静态检查。
